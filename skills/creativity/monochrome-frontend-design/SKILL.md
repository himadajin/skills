# Monochrome Frontend Design

白い紙にインクで刷ったような無彩色のデザイン言語。
装飾をすべて意味論に還元し、色・太さ・動きの代わりに
「サイズ・濃度・線種」で階層と状態を表現する。
目指す佇まいは「企業の広告」ではなく「よく組まれた技術ドキュメント」。

## 読み方

`references/design-system.md` は媒体を問わず読む共通の核で、
そこに媒体ごとの仕様を重ねる。

| 対象 | 読むもの |
|---|---|
| すべての作業 | `references/design-system.md` |
| Web サイト・アプリの UI | + `references/interaction.md`。実装は `references/media/web.md` |
| 単発の HTML | + `references/interaction.md`。`assets/starter.html` をコピーして書き換える（`assets/tokens.css` 組み込み済み） |
| スライド | + `references/media/slides.md`。インタラクション語彙は休眠 |
| markdown から変換する資料・図版・印刷 | + `references/media/documents.md`。実装は `assets/document.css` をコピーして調整する |

HTML で作る成果物がどちらの行かは「読者が hover のある画面で読むか」で決める。
ブラウザで開いて読むなら、インタラクション拡張を重ねる「単発の HTML」として組む。
markdown 由来の文書や印刷・PDF 化が主目的なら、
核とリンクの意味論だけで組む「資料」とする。

## 核ルール

公理の骨子。トークン値・サイズ・比率の正本は `references/design-system.md`。

1. **パレットは無彩色 4 色 + カーソルの点の 5 トークンで完結させる**
   （紙 / インク / muted / ヘアライン / カーソルの点）。
   カーソルの点（オレンジ）はワンポイントの目印にのみ許される唯一の色で、
   リンク・状態・見出しなど機能的な要素には決して使わない。青リンクも作らない。
   白い紙はこの言語の前提であり、ダークモード・反転パレットは作らない。
2. **フォントは 3 ファミリー固定。**
   本文・見出しは sans（Geist + Noto Sans JP）、コードとメタ情報は mono（Geist Mono）。
   使用ウェイトは 400 / 500 / 600 のみ。**700 とイタリックは使わない。**
3. **声の分離: 本文は sans、メタ情報は mono 大文字の単一スケール。**
   ラベル（パンくず・タグ・言語名・日付）はすべて同一仕様の 1 スケールに固定し、
   サイズを増やさず、差は濃度だけで付ける。
4. **タイポグラフィはドキュメント密度。**
   ページタイトルは本文の 1.5 倍が天井。
   階層はサイズの大差ではなく、控えめなサイズ差 + 太さ + 吸着余白で作る。
   見出しサイズは 5 段（24 / 20 / 18 / 17 / 16）で打ち止めにする。
   さらに深い階層はサイズを増やさず、まず濃度を落とし、
   それでも足りなければメタラベルの声に切り替えて区別する。
   スライドでは基準サイズだけを置き換え、比率を保つ（`media/slides.md`）。
5. **余白は役割別 6 段ラダーから選ぶ。**
   ラダーが縛るのはブロック間の余白（段落・見出し・セクションの margin、骨格の区切り）。
   コンポーネント内部の padding は対象外だが、
   「意味を 1 文で言えない差は作らない」は同じく適用される。
   見出しは中身に吸着させる（上広:下狭 = 4:1）。
6. **影・グラデーション・波線・角丸を使わない**（インラインコードの角丸のみ許容）。
   状態や重要度の差は濃度（インクの透明度、35 / 50 / 70% の 3 段）で作り、
   色相を変えない。
   アクセシビリティなど機能要求と濃度指定が衝突したら機能が勝つ。
   濃度は必要なだけ引き上げてよいが、新しい信号は足さない。
7. **コードは白い紙の上の引用面。**
   地は紙と同色 + 1px インク枠 + 角丸なし。シンタックス配色は抑制的なライトテーマ。
   黒地のコード面は作らない。

## インタラクション拡張（Web/UI のみ）

hover と遷移が存在する媒体でだけ、`references/interaction.md` の語彙を重ねる。

8. **インクの意味論: 破線は行ける場所、実線はいま居る場所、濃度は状態、
   面と枠は計器を表す。**
   リンクは破線下線、hover でインクが濃くなる。
   現在地（ナビ・タブ・トグルの選択中）は実線下線。
   インタラクティブ要素のうち面（背景色）と枠線を持てるのは計器だけである。
   計器はコピーボタンのようにその場で動く道具を指す。
   リンクの hover に面を出さない。
   例外: 図版・グラフの内部ではインクの意味を本文とは別に定めてよく、
   破線を系列・予測に使える。
9. **クロームは 3 帯構造。**
   クローム帯（ヘッダー等）は半透明ガラスの浮遊層、
   ステージは全ページで一定の高さの静寂、
   コンテンツ帯は紙。パンくずはステージの下でタイトルの eyebrow にする。
   ページ内ツールバーはバーではなく「計器」の見た目にし、クロームと格を分ける。
10. **動きはほぼゼロ。**
    hover による移動・浮き上がり・バウンスは使わない。
    transition は色・線・濃度のみ。
    深度は影ではなくガラスとヘアラインで表現する。

## 導出規則

ルールは網羅ではなく公理である。書かれていないものは、
次の問いで公理から導出する。

- それはサイトレベルの骨格である建築か、その場の道具である計器か。
- （UI なら）行ける場所か、いま居る場所か。
- 付けようとしている差（サイズ・濃度・線種・余白）は何の意味を運ぶか。

**意味を 1 文で言えない差は作らない。1 つの区別に信号は 1 つ。
迷ったら最も地味な選択をとる。**

## 手順

1. **計画**: 書き始める前に、媒体・3 帯の構成（UI のみ）・使うインクの種類・
   主要ブロックのラダー割当・カーソルの点の有無を、数行で宣言する。
   宣言を核ルールと導出規則に照らし、逸脱と
   「意味を言えない差」を直してから実装に入る。
2. **実装**: 読み方の表にある入口から。
   成果物に書くコメントは英語で、コードから読み取れない制約だけを残す。
   コンテンツ（本文・図表・コード例の中身）の言語は文書自身に従う。
3. **検証**: まず掃き掃除として、禁止事項（700 以上・イタリック / 影・グラデーション・
   波線 / 角丸 / トークン外の色）を出力ファイルに対して検索して潰す。
   検索パターンは出力の語法に合わせて自分で組む
   （素の CSS なら `font-weight`・hex 値、Tailwind なら
   `font-bold`・`shadow-*`・`rounded`・色クラスなど）。
   その後、下のチェックリストを確認する。
   レンダリングできる環境ではブラウザで開いて目視する。
   制作が長引いたときは、新鮮なコンテキストのサブエージェントに
   成果物とチェックリストを渡して検査させる。

## 完成前チェックリスト

- [ ] 破線がリンク以外（図版内部を除く）に、実線下線が現在地以外に使われていない（UI）
- [ ] リンクの hover が「インク濃く + 破線出現」であり、背景面が出ていない（UI）
- [ ] メタラベルが単一スケール（サイズ 1 種・mono・大文字）に揃っている
- [ ] 見出しが中身に吸着している（上広:下狭 = 4:1）
- [ ] 余白がラダーの 6 値から選ばれ、役割に対応している
- [ ] コード面が白地 + 1px インク枠 + 角丸なしである
- [ ] （UI の場合）クローム/ステージ/コンテンツの 3 帯が成立し、
      ステージ高さが全ページで一定である
- [ ] 新しく作った差それぞれについて、それが運ぶ意味を 1 文で言える
