# Monochrome Frontend Design

白い紙にインクで刷ったような無彩色のデザイン言語。
装飾をすべて意味論に還元し、色・太さ・動きの代わりに
「サイズ・濃度・線種」で階層と状態を表現する。
目指す佇まいは「企業の広告」ではなく「よく組まれた技術ドキュメント」。

## 読み方（ルーティング）

| 対象 | 読むもの |
|---|---|
| すべての作業 | `references/design-system.md`（静的核） |
| Web サイト・アプリの UI | + `references/interaction.md`。実装は `references/media/web.md` |
| 単発の HTML | + `references/interaction.md`。`assets/starter.html` をコピーして書き換える（`assets/tokens.css` 組み込み済み） |
| スライド | + `references/media/slides.md`。インタラクション語彙は休眠 |
| 資料・図版・印刷 | 静的核のみ。16px 基準の比率をそのまま適用 |
| 表・グラフなど特定の型 | `references/patterns/` に判例があれば読む。無ければ導出規則で作る |

## 核ルール（静的核）

1. **パレットは無彩色 4 トークン + カーソルの点で完結させる。**
   `#fafafa`（地）/ `#171717`（インク）/ `#f5f5f5`（muted）/ `#ebebeb`（ヘアライン）。
   オレンジ `#ffc799` は「カーソルの点」——ワンポイントの目印
   （カーソル矩形・ロゴ的要素）にのみ許される唯一の色。
   リンク・状態・見出しなど機能的な要素には決して使わない。青リンクも作らない。
2. **フォントは 3 ファミリー固定。**
   本文・見出し: Geist、日本語フォールバック: Noto Sans JP、コードとメタ情報: Geist Mono。
   使用ウェイトは 400 / 500 / 600 のみ。**700 とイタリックは使わない。**
3. **声の分離: 本文は sans、メタ情報は mono 大文字の単一スケール。**
   ラベル（パンくず・タグ・言語名・日付）はすべて同一仕様:
   本文の約 70% のサイズ（16px 基準で 11px）・weight 400・tracking +0.10em・大文字。
   サイズは 1 種類に固定し、静的 45〜55% / インタラクティブ 65% と濃度だけで差を付ける。
4. **タイポグラフィはドキュメント密度。**
   ページタイトルは本文の 1.5 倍（16px 基準で 24px）を天井に semibold。
   階層はサイズの大差ではなく、控えめなサイズ差 + 吸着余白で作る。
   本文行間は 1.65（和欧混在の下限 1.6 を割らない）。
   スライドでは基準サイズだけを置き換え、比率を保つ（`media/slides.md`）。
5. **余白は役割別 6 段ラダーから選ぶ。**
   同一物の内部(4) / 見出しと中身の接続(8) / ブロックの区切り(16) /
   小さな話題の切り替え(24) / 大きな話題の切り替え(32) / ページレベル(48)。
   見出しは中身に吸着させる（上広:下狭 = 4:1、h2 なら上 32 / 下 8）。
6. **影・グラデーション・波線・角丸を使わない**（インラインコードの角丸 4px のみ許容）。
   状態や重要度の差は濃度（インクの透明度）で作り、色相を変えない。
7. **コードは白い紙の上の引用面。**
   地は紙と同色 + 1px インク枠 + 角丸なし。
   ヘッダーは背景なし・ヘアライン下線 + mono 大文字の言語ラベルのみ。
   シンタックス配色は抑制的なライトテーマ（min-light 系）。黒地のコード面は作らない。

## インタラクション拡張（Web/UI のみ）

hover と遷移が存在する媒体でだけ、`references/interaction.md` の語彙を重ねる。

8. **インクの意味論: 「破線＝行ける、実線＝いま居る、濃度＝状態」。**
   リンクは破線 1px（インク 35%）、hover でインクが濃くなり破線が現れる。
   現在地（ナビ・タブ・トグルの選択中）は実線 2px・インク 100%。
   面（背景色）と枠線は「計器」（コピーボタン等のその場で動く道具）専用。
   リンクの hover に面を出さない。
   例外: 図版・グラフの内部は別名前空間（破線を系列・予測に使える）。
9. **クロームは 3 帯構造。**
   クローム帯（ヘッダー等）＝半透明ガラスの浮遊層 / ステージ＝一定の静寂（48px）/
   コンテンツ帯＝紙。パンくずはステージの下でタイトルの眉（eyebrow）にする。
   ページ内ツールバーはバーではなく「計器」の見た目にし、クロームと格を分ける。
10. **動きはほぼゼロ。**
    hover による移動・浮き上がり・バウンスは使わない。
    transition は色・線・濃度のみ 130〜200ms。
    深度は影ではなくガラス（半透明 + blur）とヘアラインで表現する。

## 導出規則

ルールは網羅ではなく公理である。ルーティングにも判例にも無いものは、
次の問いで公理から導出する:

- それは建築（サイトレベルの骨格）か、計器（その場の道具）か。
- （UI なら）行ける場所か、いま居る場所か。
- 付けようとしている差（サイズ・濃度・線種・余白）は何の意味を運ぶか。

**意味を 1 文で言えない差は作らない。1 つの区別に信号は 1 つ。
迷ったら最も地味な選択をとる。**

## 手順

1. **計画**: 書き始める前に数行で宣言する——
   媒体 / （UI なら）3 帯の構成 / 使うインクの種類 /
   主要ブロックのラダー割当 / カーソルの点の有無。
2. **批評**: 宣言を核ルールと導出規則に照らし、
   逸脱と「意味を言えない差」を直してから実装に入る。
3. **実装**: ルーティング表の入口から。
4. **検証**: `scripts/validate.sh <出力ファイル...>` を実行してエラー 0 を確認し、
   下のチェックリストを目視で確認する。

## 完成前チェックリスト

機械検査（validate.sh）: 700・イタリック / 影・グラデーション・波線 /
角丸 / トークン外の色。

目視:

- [ ] 破線がリンク以外（図版内部を除く）に、実線下線が現在地以外に使われていない（UI）
- [ ] リンクの hover が「インク濃く + 破線出現」であり、背景面が出ていない（UI）
- [ ] メタラベルが単一スケール（サイズ 1 種・mono・大文字）に揃っている
- [ ] 見出しが中身に吸着している（上広:下狭 = 4:1）
- [ ] 余白がラダーの 6 値から選ばれ、役割に対応している
- [ ] コード面が白地 + 1px インク枠 + 角丸なしである
- [ ] （UI の場合）クローム/ステージ/コンテンツの 3 帯が成立し、
      ステージ高さが全ページで一定である
- [ ] 新しく作った差それぞれについて、それが運ぶ意味を 1 文で言える
